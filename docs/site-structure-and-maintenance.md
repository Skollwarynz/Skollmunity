# Skollmunity site structure and maintenance guide

Last reviewed: 18 October 2026

## What the site is

Skollmunity is a static Jekyll site published by GitHub Pages at `https://skollmunity.github.io`. Jekyll converts Markdown content and Liquid templates into static HTML. There is no database or server application to maintain.

## Repository map

| Path | Purpose |
| --- | --- |
| `_config.yml` | Site title, URL, author data, permalink rules, plugins, and build exclusions. |
| `_posts/` | Published articles. Files use `YYYY-MM-DD-title.md`. |
| `_drafts/` | Unpublished articles shown only with `jekyll serve --drafts`. |
| `_layouts/` | Page shells for the homepage, posts, pages, and category pages. |
| `_includes/` | Shared head, header, and footer HTML. |
| `assets/css/style.css` | Site-wide visual styles and responsive rules. |
| `assets/images/` | Local image assets. Keep source and license information with each new image. |
| `about.md`, `art.md`, `categories.html` | Standalone pages. |
| `copyright.md` | Copyright, attribution, fair-use, and takedown policy. |
| `robots.txt` | Crawler instructions and the public sitemap URL. |
| `Gemfile` | Ruby and Jekyll plugin dependencies. |
| `.github/workflows/deploy.yml` | GitHub Actions build and GitHub Pages deployment. |

The generated `_site/` directory is disposable build output and should not be edited or committed.

## How to edit an article

Create a file such as `_posts/2026-10-18-new-analysis.md` with front matter:

```yaml
---
layout: post
title: "Article title"
date: 2026-10-18 12:00:00 +0200
categories: ["Color Theory"]
tags: ["color", "visual analysis"]
image: "/assets/images/2026/10/cover.jpg"
---
```

Put the image in `assets/images/` and use a local path beginning with `/assets/images/`. The post template links the cover image directly to its full local asset. Inline Markdown images should also be wrapped in a link to either the local asset or the original source page, for example:

```markdown
[![Descriptive alternative text](/assets/images/2026/10/example.jpg)](/assets/images/2026/10/example.jpg)
```

For a third-party image, record the creator, source URL, license, and any required attribution in the article or in a nearby credits section. A direct link is useful for attribution and traceability, but it does not create a license or make an unlicensed image lawful.

## How to edit the design

Change colors, spacing, typography, and responsive behavior in `assets/css/style.css`. Change shared navigation and footer links in `_includes/header.html` and `_includes/footer.html`. Change the document head, canonical URL, social metadata, and Search Console meta tag in `_includes/head.html`. Change the structure of individual page types in `_layouts/`.

Keep article text in Markdown rather than placing article-specific markup in a layout. After a layout change, check the homepage, one category page, one article, the About page, and the copyright page.

## Local validation

From the repository root:

```bash
bundle install
bundle exec jekyll build
bundle exec jekyll serve
```

The build must finish without an error. The build output should contain `index.html`, `robots.txt`, `feed.xml`, `sitemap.xml`, and the Google verification HTML file. Do not edit `_site/` directly; rebuild it instead.

## Google Search Console setup

The repository contains two verification methods for the URL-prefix property:

1. The HTML file `googlefXatqtLtaIHxqXnp4RGIiOk9af8qpNTlLmqB3LQZTRk.html` is published at the site root.
2. The shared head includes the supplied `google-site-verification` meta tag.

`skollmunity.github.io` is the default GitHub Pages subdomain. You do not control the `github.io` DNS zone, so you cannot add a TXT record for this address at a personal domain provider. Google requires DNS verification for a Domain property, while this site is ready for a URL-prefix property. Add `https://skollmunity.github.io/` as a URL-prefix property and choose HTML file or HTML tag verification:

```text
URL-prefix: https://skollmunity.github.io/
HTML file: googlefXatqtLtaIHxqXnp4RGIiOk9af8qpNTlLmqB3LQZTRk.html
HTML tag: google-site-verification=fXatqtLtaIHxqXnp4RGIiOk9af8qpNTlLmqB3LQZTRk
```

The HTML file and tag are already in the repository and are published by the build. After verification, submit `https://skollmunity.github.io/sitemap.xml` in Search Console. The sitemap is generated by `jekyll-sitemap` during the GitHub Pages build. If you later connect a custom domain that you own, you can create a separate Domain property and place Google's TXT record in that domain's DNS zone.

## Release checklist

Before pushing to `main`, confirm:

- `bundle exec jekyll build` passes.
- The site URL in `_config.yml` is exactly `https://skollmunity.github.io`.
- Every new image has a local asset path or a traceable original source and license.
- Every content image is clickable to its asset or source page.
- `robots.txt` points to `https://skollmunity.github.io/sitemap.xml`.
- GitHub Actions finishes the Pages deployment successfully.
- Search Console verification is complete and the sitemap URL has been submitted.
